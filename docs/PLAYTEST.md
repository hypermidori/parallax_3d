# 確認手順

`npm run dev` または `tools/start-game.ps1` で起動し、`http://127.0.0.1:5180/` を開く。

1. 出撃し、マウス、またはタッチした位置を基点とするバーチャルパッドで照準を動かす。主人公の追従と左右のアニメーションを確認する。
2. 敵編隊に照準を合わせて長押し。複数のロックが点灯したら離し、曲がるレーザーと撃破を確認する。
3. 敵の赤い予告表示の後、照準を動かして弾から離れる。通常弾は自動発射される。
4. Escape / Pでポーズし、再開する。HPが0になるとリトライできる。
5. 約2分の道中の後、四脚戦車GRENDELが出現。耐久力に応じて攻撃が3段階に変化する。
6. ボスを撃破してリザルトへ進み、もう一度出撃できることを確認する。

## 自動検証

`npm test` はロック数の上限、破壊済みターゲット、解除・キャンセル、高速弾のすり抜け、ルート接線を検証する。

`scripts/verify-browser.mjs` はPlaywrightを利用する。Playwrightが解決可能な環境で開発サーバーを起動してから実行する。`NODE_PATH` に既存のPlaywrightパッケージを含むディレクトリを指定してもよい。`BROWSER_EXE` でChromium系ブラウザの実行ファイル、`GAME_URL` でURLを変更できる。

```powershell
node scripts/verify-browser.mjs
```

結果は `output/night-city/browser-verification.json`、実機描画のスクリーンショットは `screenshots/` に保存される。

通し確認は `?debug=1&autopilot=1&speed=8&invulnerable=1` を使う。8倍速・自動照準・無敵で進行を確認するためのモードで、通常プレイの難易度を保証するものではない。被弾・死亡・リトライは別途検証する。通常URLではこれらの補助機能は無効。

ブラウザ検証はデスクトップEdge。タッチは390×844の端末エミュレーション、ゲームパッドはGamepad APIの入力を模擬する。スマホ実機・実コントローラーの性能と接続互換性は未検証。

## 2026-09-07の結果

ロジックテスト5件、ブラウザ検証15項目を通過。開発サーバーと製品ビルドの両方でステージクリアを確認した。製品ビルドでは読み込み失敗・ブラウザ例外なし。記録は `verification-2026-09-07.json`。Viteのビルドは成功し、Three.jsの約517KBのバンドルにサイズ警告が残る。

横画面の強制は撤去。390×844の縦画面で出撃できること、縦横の回転後もプレイが続くこと、全画面化・向き固定APIが呼ばれないことを確認する。回転時のタッチ解除は維持する。

## バーチャルパッドの検証

node scripts/verify-touch-pad.mjs で、タップ時の位置維持、デッドゾーン、倒し続けた際の移動、中立での停止、再タップ、上下40〜70%・左右35〜65%の制限、キャンセル、ロックと発射、回転後の入力解除を確認する。実際のタッチイベントをブラウザへ送り、結果を output/night-city/touch-pad-verification.json に保存する。照準の円と取得判定は同じ画面上の半径を使う。スマホ実機の操作感は未確認。


## ボス戦中の背景ループ（2026-09-07）

Blenderで道中10区画とループ4区画を再生成した。全98メッシュにUVと埋め込み画像テクスチャがあり、ゲーム側では8スロットのループ区画を共有ジオメトリ・材質で再配置する。

- ロジック・GLB検証10件を通過。道中の接続座標、4区画の道路端、画像テクスチャ、ゲームのルートと書き出した道路の一致、24時間相当の区画割り当てを検証した。
- 通常のブラウザ検証19項目を通過。進行距離約2150m、約154秒でボス撃破・クリアに到達し、リトライも正常。タッチ・回転・入力キャンセルを含め、ブラウザ例外と読み込み失敗はなかった。
- 長時間試験47項目を通過。8倍速でゲーム内約729秒（ボス戦約609秒）、約10.2kmまで前進した。ボスとの距離は68mを維持し、区画再配置後も表示範囲に欠落がなかった。検証終盤の描画リソースはジオメトリ124個・テクスチャ19個で、区画の周回に伴って増え続けることはなかった。
- ループ入口と周回後のスクリーンショットを目視確認。市街地の窓、路面、歩道、橋を維持した状態で、道路が連続している。
- 製品ビルド成功。既存のThree.jsバンドルサイズ警告は残る。

再実行: node scripts/verify-city-loop.mjs
記録: output/night-city/city-loop-verification.json
画像: screenshots/loop-*.png

長時間試験だけは debug=1 と endlessBoss=1 でボスへのダメージを無効にする。通常のクリア試験ではこの設定を使わない。24時間相当の確認は区画配置の数値テストであり、実時間24時間のブラウザ連続稼働試験ではない。スマホ実機の性能は未検証。
