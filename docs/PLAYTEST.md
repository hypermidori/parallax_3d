# 確認手順

`npm run dev` または `tools/start-game.ps1` で起動し、`http://127.0.0.1:5180/` を開く。

1. 出撃し、マウスで照準を動かす。主人公の追従と左右のアニメーションを確認する。
2. 敵編隊に照準を合わせて長押し。複数のロックが点灯したら離し、曲がるレーザーと撃破を確認する。
3. 敵の赤い予告表示の後、照準を動かして弾から離れる。通常弾は自動発射される。
4. Escape / Pでポーズし、再開する。HPが0になるとリトライできる。
5. 約2分の道中の後、四脚戦車GRENDELが出現。耐久力に応じて攻撃が3段階に変化する。
6. ボスを撃破してリザルトへ進み、もう一度出撃できることを確認する。

## 自動検証

`npm test` はロック数の上限、破壊済みターゲット、解除・キャンセル、高速弾のすり抜け、ルート接線を検証する。

`scripts/verify-browser.mjs` はPlaywrightを利用する。Playwrightが解決可能な環境で開発サーバーを起動してから実行する。`NODE_PATH` に既存のPlaywrightパッケージを含むディレクトリを指定してもよい。`BROWSER_EXE` でChromium系ブラウザの実行ファイル、`GAME_URL` でURLを変更できる。

```powershell
node scripts/verify-browser.mjs
```

結果は `output/night-city/browser-verification.json`、実機描画のスクリーンショットは `screenshots/` に保存される。

通し確認は `?debug=1&autopilot=1&speed=8&invulnerable=1` を使う。8倍速・自動照準・無敵で進行を確認するためのモードで、通常プレイの難易度を保証するものではない。被弾・死亡・リトライは別途検証する。通常URLではこれらの補助機能は無効。

ブラウザ検証はデスクトップEdge。タッチは390×844の端末エミュレーション、ゲームパッドはGamepad APIの入力を模擬する。スマホ実機・実コントローラーの性能と接続互換性は未検証。

## 2026-09-07の結果

ロジックテスト5件、ブラウザ検証15項目を通過。開発サーバーと製品ビルドの両方でステージクリアを確認した。製品ビルドでは読み込み失敗・ブラウザ例外なし。記録は `verification-2026-09-07.json`。Viteのビルドは成功し、Three.jsの約517KBのバンドルにサイズ警告が残る。

横画面対応後はスマホの縦画面を回転待ち表示とし、844×390でタッチ操作を確認する。縦への回転でポーズし、時間・被弾が進まないこと、横に戻しても自動再開しないことを検証する。ブラウザテストでは全画面化と向き固定APIの拒否を模擬して、手動回転で復帰できる経路を確認する。向き固定が実機で成功するかはOS・ブラウザ依存で、実機検証は未実施。
